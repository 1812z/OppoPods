### miuix 版本升级 0.9.2 → 0.9.4 + folmeSpring 破坏性变更

只改 `gradle/libs.versions.toml` 一处：`miuix = "0.9.2"` → `"0.9.4"`（5 个模块共用同一 `version.ref`，联动生效）。

**⚠️ 更正：0.9.4 的 `folmeSpring` 只有 `damping` + `response` 两个参数，没有 `stiffness`。**

直接读 0.9.4 sources jar 里 `miuix-ui-android/.../anim/MiuixEasing.kt` 实测：
```kotlin
fun <T> folmeSpring(
    damping: Float,
    response: Float,
    visibilityThreshold: T? = null,
): SpringSpec<T> {
    val stiffness = ((2.0 * PI / response) * (2.0 * PI / response)).toFloat()
    return spring(dampingRatio = damping, stiffness = stiffness, visibilityThreshold = visibilityThreshold)
}
```
- 之前"三参数 `stiffness/damping/response`"的说法是从旧版 metadata 反推的**错误结论**，已被源码推翻。
- 报错 `No parameter with name 'stiffness' found` + `No value passed for parameter 'response'` 的真因：`stiffness` 根本不存在，且缺 `response`。
- **正确写法（最终确认，2026-09-28 编译通过）**：`folmeSpring(damping = 0.9f, response = 0.3f)` —— **不写泛型实参**，让上下文推断出 `IntSize`。
- ⚠️ 曾经的错误尝试：写 `folmeSpring<Int>(...)` 会报
  `Argument type mismatch: actual type is 'SpringSpec<Int>', but 'FiniteAnimationSpec<IntSize>' was expected`。
  `expandVertically`/`shrinkVertically` 需要的是 `FiniteAnimationSpec<IntSize>`（动画目标是尺寸，不是 Int），
  手动写 `<Int>` 会强行把 T 固定成 Int，与目标类型冲突；不写泛型则编译器自动推断为 `IntSize`。
- 参考 miuix 自身用法：`TopAppBar.kt` 里 `folmeSpring<Float>(...)`（那是动画目标是 Float 的场景，泛型与上下文一致时才可显式写）、
  `NavigationRail.kt` 里 `folmeSpring(damping = 1f, response = 0.35f, visibilityThreshold = 0.001f)`（不写泛型）。
- **教训**：泛型函数在 Compose 动画 API 里，绝大多数情况应省略泛型实参交给上下文推断；只有动画目标类型与推断结果明确一致时才显式写。

### miuix 0.9.4 导航包迁移：`miuix-navigation3-ui` → `miuix-nav`

0.9.4 起 `miuix-navigation3-ui-android`（包 `androidx.navigation3.*`）被 `miuix-nav`（包 `top.yukonga.miuix.kmp.nav.core`）取代，包名与 API 全换。

依赖（`gradle/libs.versions.toml`）：
```toml
miuixNav = "0.9.4"
miuix-nav = { module = "top.yukonga.miuix.kmp:miuix-nav", version.ref = "miuixNav" }
```
`app/build.gradle.kts` 用 `implementation(libs.miuix.nav)`。`navigation3-runtime` 已从依赖与版本目录中**移除**（`androidx.navigation3` 已无任何引用；`Screen : NavKey` 改用 miuix 自己的 `NavKey`）。

**新 API 真实签名（0.9.4 sources jar 实测，非猜测）**：
```kotlin
typealias NavBackStack = SnapshotStateList<NavKey>
interface NavKey   // 标记接口，路由层级加 @Serializable

// 公开重载：content 是 DSL lambda，不是 entries
fun NavDisplay(
    backStack: NavBackStack,
    modifier: Modifier = Modifier,
    onBack: () -> Unit = { backStack.removeLastOrNull() },
    transition: NavTransition = NavTransitions.MiuixDefault,
    effects: NavDisplayEffects = NavDisplayEffects(),
    content: NavEntryBuilder.() -> Unit,
)
// 另有 navController 重载；低层 entryProvider 重载是 internal，外部不可用
```
**关键：0.9.2 的老写法 `entries = <entryProvider 函数>` 在 0.9.4 已不存在**，且 `entryProvider(...)` 顶层工厂函数与 `NavEntry 公开类型` 均为 `internal`，外部模块无法直接用。正确写法是把 DSL 块存成 lambda 变量再传给 `content`：
```kotlin
val navContent: NavEntryBuilder.() -> Unit = {
    entry<Screen.Main> { ... }
    entry<Screen.About> { ... }
}
NavDisplay(backStack = backStack, onBack = {...}, content = navContent)
```
需 import：`NavDisplay` / `NavKey` / `NavEntryBuilder` / `entry`（`entry` 和 `entryProvider` 同包，但只有 `entry` 是公开扩展）。

backStack 声明类型改为 `NavBackStack`（= `SnapshotStateList<NavKey>`）。`App.kt` 里构造：
```kotlin
val backStack: NavBackStack = remember { mutableStateListOf<NavKey>(Screen.Main) }
```
`MainUI(backStack: NavBackStack)`。（若写 `mutableStateListOf<Screen>` 会因泛型不变性无法赋给 `SnapshotStateList<NavKey>`。）

路由需 `@Serializable`：官方要求 route 层级标注（`rememberNavBackStack` 持久化时是硬要求；本处用 `mutableStateListOf` 属内存态，标注是为合规与将来持久化）。

反查方法：`~/.gradle/caches/modules-2/files-2.1/top.yukonga.miuix.kmp/miuix-nav-android/0.9.4/*/miuix-nav-android-0.9.4-sources.jar` —— **有 sources jar 时优先直接读 .kt 源码**，比 javap/strings 反查 metadata 快且准得多。
